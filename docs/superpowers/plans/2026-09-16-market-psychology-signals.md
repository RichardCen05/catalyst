# Market Psychology Signals — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:executing-plans` (or `superpowers:subagent-driven-development`) to run this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Turn five observations from the 2026-09-16 practitioner interview into shipped, citation-backed features: user-tunable research thresholds, institutional distribution ("whale") detection, unexplained co-movement ("panic contagion") flagging, a narrative-versus-financials contradiction check, and an honest leadership-change surface.

**Architecture:** Three new deterministic modules under `lib/agent/` (`distribution.ts`, `contagion.ts`, `fundamental-check.ts`), one build-script extension that lifts already-recorded raw JSON into the typed bundle, and one extension of the existing `InvestorResearchPlaybook` threshold mechanism. No new pillar, no new page, no new data vendor. Every new number is computed in TypeScript and carries a `Citation`; the LLM layer is untouched.

**Tech Stack:** Next.js 16 App Router, TypeScript, Zod, Zustand (persisted playbook), Vitest, Playwright, `scripts/build_market_data.py`. No new dependency.

**Data posture:** every raw file this plan needs is already on disk in `data/sectors/` (filings, quarterly financials, daily series for 18 symbols, broker summary for 6, corporate actions, IHSG). **Sectors credit cost of this plan is zero** — it reads recordings, it does not call the API. Only Task 12 (optional coverage widening) spends credit, and it stays gated behind the existing budget/ledger path.

---

## Global Constraints

- **No invented numbers.** Every metric added here is computed from a recorded field and cited with `lib/agent/citations.ts`. If a source is missing, the feature emits a gap row via `deriveMissingEvidence` — never a placeholder value.
- **No new `PillarKey`.** `PillarKey` is a fixed 4-tuple baked into `profileSchema` (`z.array(pillarSchema).length(4)` in `lib/schemas.ts:16`), `pillarOrder`, the store, and the UI. New evidence attaches to the existing `concentration` pillar as extra `metrics` + `calculation` rows, or to `contradictions` / `counterEvidence` / `unresolvedQuestions` on the case.
- **Correlation is not causation, and the UI must say so.** Contagion output is a *question to check*, never a verdict, never a recommendation. It renders with a distinct visual treatment from causal edges.
- **Negotiated-market (pasar nego) block trades are NOT available** from Sectors v2. The broker-summary payload (`data/sectors/v2_broker-summary_*_top.json`) has `broker_code`, `net_idr`, `buy_idr`, `sell_idr` and no market-board split. Task 5 ships a *proxy* and labels it a proxy; Task 6 ships the real substitute — IDX holder-change filings. The gap itself gets an explicit line in the gap list.
- **No reputation scores for individuals.** There is no recorded track-record source. Task 9 surfaces the recorded leadership-change fact plus an explicit "rekam jejak individu: tidak terekam" gap. Fabricating a CEO score would violate the project's own citation rules and is out of scope.
- `pnpm test` must stay green with `AGENT_MODE=deterministic` and no network.
- The bundled `lib/data/market.generated.ts` is only ever regenerated by running `scripts/build_market_data.py` locally against `data/sectors/`; runtime never writes it.

## Phase A — User-tunable thresholds (Feature 1)

**Design decision:** the knobs go in `InvestorResearchPlaybook`, **not** `lib/settings.ts`. Those are two different things and must not merge:

| | `lib/settings.ts` | `InvestorResearchPlaybook` |
|---|---|---|
| Scope | server-global, one per deployment | per user |
| Storage | GCS `catalyst/config/settings.json` | Zustand persist (browser) + GCS backup via `/api/memory` (validated against `playbookSchema`; C6) |
| Purpose | operator ops gate (Sectors credit spend) | research judgment parameters |
| Already threaded to engine | no | yes — `playbookSchema` rides on `/api/analyze`, `/api/causal-graph`, `/api/chat` |

`relevanceFloor` already proves the pattern end to end (`lib/agent/engine.ts:50` `relevanceFloorFor()`, slider at `app/playbook/page.tsx:126`). This phase generalises it.

### Task 1 — Thresholds in the type + schema

- [ ] Add to `InvestorResearchPlaybook` in `lib/types.ts` (keep `relevanceFloor` at top level for backward compatibility with persisted stores):
  ```ts
  /** Ambang yang bisa diatur pengguna. Semua opsional; default ada di lib/agent/thresholds.ts. */
  thresholds?: {
    /** Porsi nilai peserta teratas yang dianggap "Concentrated Flow". Default 0.42. */
    concentrationFloor?: number;
    /** Skor z volume tahan-pencilan minimum sebelum anomali ditandai. Default 3. */
    volumeZFloor?: number;
    /** Penurunan harga harian (absolut) yang memicu pemeriksaan penularan. Default 0.04. */
    contagionDropFloor?: number;
    /** Korelasi imbal hasil minimum sebelum co-movement dianggap layak diperiksa. Default 0.5. */
    contagionCorrelationFloor?: number;
    /** Nilai bersih pelepasan institusi (IDR) minimum sebelum ditandai distribusi. Default 1e11. */
    distributionValueFloor?: number;
  };
  ```
- [ ] Create `lib/agent/thresholds.ts`: export `DEFAULT_THRESHOLDS` and `resolveThresholds(playbook?)` returning a fully-populated object. One resolver, one default table, no defaults scattered in call sites.
- [ ] Move the existing `relevanceFloorFor` default (85) into that table; keep the exported function name so no call site breaks.
- [ ] Extend `playbookSchema` in `lib/schemas.ts` with a matching `thresholds` object, every field `.optional()` with `.min()/.max()` bounds (a threshold outside its bound is a 400, not a silent clamp).
- [ ] Test `tests/thresholds.test.ts`: defaults resolve when playbook absent; partial override keeps other defaults; out-of-bound value rejected by schema.

### Task 2 — Engine reads thresholds instead of literals

- [ ] `lib/agent/engine.ts:367` — replace the hardcoded `concentration.topBuyerShare >= 0.42` with the resolved `concentrationFloor`.
- [ ] Same for the volume z-score floor (in `calculateVolumeSignal`'s caller) — locate the literal, route it through `resolveThresholds`.
- [ ] **Every threshold that changes an outcome must push an `AppliedPlaybookRule`** into the existing `ruleTrace` / `appliedRules` array, e.g. `{ kind: "materiality", rule: "Ambang konsentrasi 0.30 (bawaan 0.42)", effect: "Status konsentrasi naik ke Concentrated Flow" }`. A user who moves a slider must be able to see exactly which verdict moved because of it.
- [ ] Test `tests/engine.test.ts` additions: same fixture + lowered `concentrationFloor` flips the pillar status AND appends exactly one `appliedRules` entry; default playbook produces byte-identical output to today (regression guard).

### Task 3 — Sliders on the playbook page

- [ ] `app/playbook/page.tsx` — add a "Ambang penilaian" section modelled on the existing relevance-floor control at line 126. One labelled range input per threshold, each showing current value, the default, and a "diubah dari bawaan" badge when different.
- [ ] Add `setThreshold(key, value)` to `lib/store.ts` next to `setRelevanceFloor`, plus a "kembalikan ke bawaan" action per row.
- [ ] Copy rule: each slider's helper text says what it *changes*, not what it *predicts* (e.g. "Menaikkan ambang membuat lebih sedikit kasus berstatus Concentrated Flow" — never "meningkatkan akurasi").

## Phase B — Institutional distribution / "whale" (Feature 2)

**What the data actually supports.** `data/sectors/v2_filings__*_symbol-*.JK.json` carries, per IDX filing: `holder_name`, `holder_type` (`institution` / insider), `holding_before`, `holding_after`, `amount_transaction`, `transaction_type`, `timestamp`, and a `source` URL pointing at the IDX announcement PDF. Today `scripts/build_market_data.py:328-334` reads these files but keeps only the title/body text — every structured field is discarded. That is the whole feature, sitting unused on disk.

### Task 4 — Lift filings into the typed bundle

- [ ] Add `InstitutionalFlow` to `lib/types.ts`:
  ```ts
  export interface InstitutionalFlow {
    symbol: SymbolCode;
    holderName: string;
    holderType: "institution" | "insider" | "other";
    transactionType: string;
    sharesBefore: number;
    sharesAfter: number;
    sharesDelta: number;      // sharesAfter - sharesBefore, signed
    filedAt: string;          // Asia/Jakarta
    source: string;           // IDX announcement URL
  }
  ```
- [ ] Add `institutionalFlows: InstitutionalFlow[]` to `CompanyAnalysisFixture`.
- [ ] `scripts/build_market_data.py` — in the filings loop, emit the structured rows alongside the existing text event. Keep the text event (it is already cited and rendered); this adds, it does not replace. Drop rows where `holding_before`/`holding_after` are absent rather than defaulting to 0.
- [ ] Add a `citations.filing(symbol)` entry in `lib/agent/citations.ts` pointing at the IDX `source` URL, following the existing `citations.broker` shape.
- [ ] Regenerate: `python3 scripts/build_market_data.py` — commit the regenerated `lib/data/market.generated.ts` in the same commit as the script change so the bundle and its generator never drift.

### Task 5 — `lib/agent/distribution.ts`

- [ ] `netInstitutionalFlow(flows, windowStart, windowEnd)` → `{ netShares, netValue, topHolders }`, value using the fixture's `referencePrice`. Pure function, no I/O.
- [ ] `detectDistributionDivergence({ priceReturn, netValue, floor })` → flags when **price rose over the window while institutional net flow was negative beyond `distributionValueFloor`**. This is the interview's core warning ("harga naik di reguler, whale jualan") expressed in data the project actually has.
- [ ] `brokerChurnRatio(brokerEvidence)` → per broker `(buy_idr + sell_idr) / max(|net_idr|, 1)`. High churn on a top-ranked broker is the **proxy** for crossing/block activity. Name it `churnRatio`, label it in the UI as "proksi", and state in the `calculation.notes` that pasar nego is not observable in this source.
- [ ] Test `tests/distribution.test.ts`: signed delta maths; divergence fires only when both conditions hold; zero-flow symbol yields no flag and no crash; churn ratio with `net_idr = 0` does not divide by zero.

### Task 6 — Wire distribution into the case

- [ ] `lib/agent/engine.ts` `buildAnalysis()` — compute the distribution result next to the existing `concentration` block (~line 319).
- [ ] Emit the three new concentration metrics ONLY when `institutionalFlows.length > 0` (C4 — 14 symbols have empty filings; unconditional emit 500s via `enforceCitations`). Never re-add them unconditionally.
- [ ] Append to the **existing `concentration` pillar**: metrics `Aliran institusi bersih`, `Pemegang terbesar berubah`, `Rasio churn broker teratas`, each citing `citations.filing(symbol, sourceUrl)` / `citations.broker(symbol)` (C3: registry is `lib/data/fixtures.ts:58`, not `lib/agent/citations.ts`).
- [ ] When divergence fires, push the sentence into the case's `contradictions[]` (already rendered) and extend `PillarResult.protocol.challengingEvidence` — divergence is counter-evidence to a bullish read, which is exactly where the user of this app should meet it.
- [ ] Update `deriveMissingEvidence` in `lib/evidence-gaps.ts`: the existing line "Transaksi pihak terafiliasi belum diidentifikasi." now only prints when `institutionalFlows.length === 0`; add a permanent line "Transaksi pasar negosiasi tidak tersedia pada sumber terekam."
- [ ] Test: fixture with recorded filings (GOTO, BMRI, BUKA, JSMR have real rows; the rest are empty 200B files) produces metrics; an empty-filings symbol produces the gap line and no metric.

## Phase C — Unexplained co-movement / panic contagion (Feature 3)

**What it is:** the PIPA→BUVA case from the interview — an unrelated name sells off because a superficially similar one did. The recorded universe supports this fully: 18 symbols of daily OHLCV plus IHSG, same window, already bundled.

**What it must never become:** a prediction or a recommendation. Output is one falsifiable question attached to the case.

### Task 7 — `lib/agent/contagion.ts`

- [ ] `returnSeries(priceSeries)` → daily simple returns; `excessReturn` subtracts the IHSG return for the same date so a market-wide move is not mistaken for contagion.
- [ ] `pairCorrelation(a, b)` over the recorded window — plain Pearson on excess returns, with a minimum-observations guard (< 10 overlapping days → `null`, not a number).
- [ ] `fundamentallyLinked(symbolA, symbolB, { events, playbook })` → `true` when any of: a shared `impactLink` on the same event, same `sub_sector`, membership in the same `COMMODITY_EXPOSURE` leg, or an explicit `preferredComparables` entry in the user's playbook. This is the **negative** filter — a link means it is NOT unexplained.
- [ ] `detectContagionCandidates({ symbol, universe, date, thresholds })` → for a drop on `symbol` beyond `contagionDropFloor` with **no event linking to `symbol` on D or D-1**, return peers that (a) had an adverse recorded event in that window, (b) correlate above `contagionCorrelationFloor`, and (c) are **not** `fundamentallyLinked`. Each candidate carries the peer symbol, the correlation, the peer's event id, and the citations for both price series.
- [ ] Test `tests/contagion.test.ts`: excess-return maths; a market-wide IHSG drop yields zero candidates; a fundamentally-linked pair is excluded even at correlation 0.95; short overlap returns `null` rather than a fabricated correlation; a real PIPA/BUVA-shaped synthetic fixture yields exactly one candidate.

### Task 8 — Surface contagion honestly

- [ ] `lib/agent/engine.ts` — push each candidate into `unresolvedQuestions[]` as a question, phrased as one: "Penurunan {symbol} {date} tidak punya peristiwa terhubung, sementara {peer} turun setelah {event}. Korelasi imbal hasil berlebih {r}. Apakah ini penularan sentimen atau jalur fundamental yang belum terekam?"
- [ ] Add one `counterEvidence[]` entry when the drop has no linked event at all — an unexplained move is evidence against any confident narrative.
- [ ] Causal graph (`app/api/causal-graph/route.ts` + the graph builder in `engine.ts:~754`): emit co-movement edges with a distinct `basis: "Co-movement (unverified)"` and `confidence: "Low"`, rendered dashed and grey. **Never** the same visual weight as a `Causal hypothesis` edge. If the renderer cannot express a distinct style cheaply, omit the edge from the graph and leave it in the text — legibility of the causal chain outranks completeness.
- [ ] Test: graph snapshot shows the co-movement edge is distinguishable by `basis` and `confidence`; text question is present and cites both price series.

## Phase D — Narrative versus financials (Feature 4)

**Already done, do not redo:** `v2_financials_quarterly_*` is recorded for 6 symbols, lifted into `financialContext`, and rendered with citations in `app/companies/[symbol]/company-detail-client.tsx:79` and `components/research-case-workspace.tsx:82-84`. Filings already become events at relevance 95.

**The actual gap:** nothing checks whether the *narrative* the event asserts agrees with the *numbers* already on screen.

### Task 9 — `lib/agent/fundamental-check.ts`

- [ ] `directionOfFinancialTrend(financialContext, label)` → `"up" | "down" | "flat" | "unknown"` from the recorded quarterly series. Parse from the recorded numeric field, not from the `interpretation` prose.
- [ ] `checkNarrativeAgainstFinancials({ event, financialContext })` → when the event's `impactLink.direction` is `Supported` but the matching financial line trends down (or `Adverse` while it trends up), return a contradiction string naming both sides and both citations. `"unknown"` returns nothing — silence beats a guess.
- [ ] Wire into `buildAnalysis()`, appending to the existing `contradictions[]`.
- [ ] Test `tests/fundamental-check.test.ts`: agreeing pair yields nothing; opposing pair yields one contradiction carrying both citations; missing financial rows yield nothing and no throw.
